# Architecture

```
 ┌──────────── Windows PC ─────────────┐        ┌──── Relay (VPS, Docker) ────┐        ┌──── Android phone ────┐
 │ LogonUI.exe (SYSTEM, secure desktop)│        │ Caddy (TLS) → phonegate-relay│        │ PhoneGate app          │
 │  └ phonegate_cp.dll                 │        │  • auth = sign a challenge   │        │  • Keystore keys       │
 │     wraps the Password provider,    │  pipe  │  • mailboxes by key hash     │  WSS   │    (approve key needs  │
 │     filter hides other tiles        │◀──────▶│  • opaque, in-memory, TTL    │◀──────▶│    biometric per use)  │
 │ phonegate-agent (service, SYSTEM)   │  WSS   │  • no keys, no storage       │        │  • foreground service  │
 │  • TPM identity key (P-256)         │───────▶│                              │        │    keeps one socket per│
 │  • approval engine, recovery        │        └──────────────────────────────┘        │    paired PC           │
 │ PhoneGate.exe (companion, admin)    │                                                └────────────────────────┘
 │  • pairing QR, codes, history       │
 └─────────────────────────────────────┘
```

## Components

| Path | What it is |
|------|------------|
| `crates/pg-core` | The single Rust implementation of the protocol: encoding, crypto, messages, envelopes, pairing, attestation verification, recovery and offline codes, state store, IPC framing, relay client. |
| `server` | `phonegate-relay`: axum WebSocket router. Stateless and untrusted. |
| `windows/agent` | `phonegate-agent`: Windows service. `engine.rs` is platform-neutral and fully tested. `win/` holds TPM (NCrypt), DPAPI fallback, named pipes with DACLs, and posture checks. |
| `windows/credprov` | `phonegate_cp.dll`: Rust COM credential provider and filter. Every entry point is panic-guarded. |
| `windows/companion` | Tauri 2 companion app: web UI plus a Rust bridge to the agent's control pipe. |
| `android` | Kotlin / Jetpack Compose app. Its protocol module mirrors pg-core and is checked by the shared vectors. |
| `crates/pg-sim`, `tests/e2e` | Software phone, plus end-to-end tests against a real relay, including the hostile-relay suite. |
| `protocol/vectors` | Shared test vectors (generated by Rust, consumed by Kotlin). |
| `deploy` | Dockerfile, Compose and Caddy files for one-command relay hosting. |

## Unlock sequence

1. You type your password on the PhoneGate tile. The CP unpacks the Password provider's
   serialization and checks the password locally with `LogonUserW(NETWORK)`. A wrong password
   stops here, with no push.
2. The CP asks the agent (`\\.\pipe\phonegate.gate`, SYSTEM-only; the CP checks that the server is
   SYSTEM) to `begin`.
3. The agent builds an `ApprovalRequest`: random id and nonce, 60 s expiry, a 2-digit match
   number, and the account, scenario and PC name. It encrypts it with `k_pair`, signs it with the
   TPM key and sends it through the relay.
4. The phone verifies the PC signature and freshness, decrypts, and shows the visitor slip. You
   type the number and touch the sensor. The approve key signs the decision, bound to the
   request's hash.
5. The agent verifies the envelope (device key), the decision signature (approve key), the
   number, the expiry and single use. It then marks the request `approved`.
6. The CP's worker thread sees `approved` and calls `CredentialsChanged`. LogonUI re-enumerates,
   the CP reports auto-logon, and hands LogonUI the stored serialization. LSA then performs the
   normal password check.

## Trust boundaries

- **LogonUI ↔ agent:** named pipe restricted to SYSTEM. The client verifies the server token.
- **Companion ↔ agent:** named pipe restricted to SYSTEM and elevated Administrators. Turning
  protection off also needs the phone or a recovery code.
- **Agent ↔ relay ↔ phone:** untrusted transport. Everything is end-to-end signed and encrypted.
- **Phone:** approve key in the TEE/StrongBox, gated by biometrics. This is verified by attestation.
